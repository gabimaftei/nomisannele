# NOMIS ANNELE — website (v2)

The website for the Instagram shop [@nomis.annele](https://www.instagram.com/nomis.annele/):
handmade bags from worn-out denim, made by a mother and daughter. The site is in
Romanian (default) and English.

The site is plain HTML, CSS and JavaScript with no framework and no npm dependencies.
A small Cloudflare Worker adds two things: the owner panel at `/admin`, and its API at
`/api/*`. The panel saves changes by committing to the `main` branch of this repo through
the GitHub API. Everything else on the site is static files.

For the owner, there is a non-technical guide in `GHID.md`.

## 2. Running it locally

**Static preview only (no panel, no API):**

```bash
cd ~/Desktop/NomisAnnele && python3 -m http.server 4321
```

Then open <http://localhost:4321>. Do not double-click `index.html`: that opens a `file://`
address, which is not how the site is served.

**Site, panel and API together:**

```bash
node tools/dev-server.mjs          # default port 8788; or: node tools/dev-server.mjs 9000
```

It prints the site address, the panel address (`/admin/`) and a test password. The password
is new on every start and appears only in the terminal. Nothing is written to the repo, the
GitHub side lives in memory, and every publish disappears when the server stops.

What it runs: the real request handler (`handleApi` in `server/api.js`) and the real rendering
code, against an in-memory copy of the repo.

What it does **not** reproduce:

- the Workers runtime (`wrangler` / `workerd`): CPU limits and small differences in `fetch`,
  `Request` and `Response` are not tested here;
- the Cloudflare rate limiter: the local replacement only counts, and the lock never expires
  until the server restarts;
- `caches.default` expiry: the local cache ignores `max-age`;
- the `CANONICAL` redirect, `run_worker_first`, `not_found_handling` and `.assetsignore`;
- the `_headers` file: the CSP and cache headers are not sent locally, and the
  versioned-asset caching is not exercised (responses are `no-store`);
- real GitHub permissions, limits, renames and the Cloudflare build that follows a push.

Unknown addresses return `404.html` if it exists, otherwise a plain `404`.

**Build the generated files:**

```bash
node tools/build-site.mjs            # rewrites the generated files from the current data
node tools/build-site.mjs --check    # writes nothing; exits with 1 if anything would change
```

The build reads `assets/js/products.js`, `assets/js/content.js` and `data/posts.json` (if it
exists), and rewrites `products.js`, `content.js`, `data/posts.json`, `index.html`,
`404.html` and `sitemap.xml`. It never touches photos. Running it twice changes nothing.

**Tests:**

```bash
node --test
```

Run it from the repo root. On Node 24, `node --test test/` does not work (it reports
`test failed`), so use plain `node --test`. The mock GitHub reads the file list with
`git ls-files`, so `git` must be installed. At the time of writing, 30 tests pass.

If Node prints a warning about `MODULE_TYPELESS_PACKAGE_JSON`, it comes from a
`package.json` higher up in the folder tree, not from this repo. It is harmless.

There is no `package.json` in the repo, so there is nothing to `npm install`.

## 3. Data files

The panel reads these files from the repo (never from the live site) and writes them back on
every publish. Each rule below is enforced by `server/api.js` on the server, not only in the
browser.

### `assets/js/products.js`: the bags

```js
const PRODUCTS = [
  { id: 'buton', name: 'Buton', photos: 2, kind: 'umar', sold: false,
    dims: { h: 28, w: 31, d: 9 }, madeFrom: 6, tint: 'denim', badge: null,
    ro: { tagline: '…', description: '…', pockets: '…', closure: '…' },
    en: { tagline: '…', description: '…', pockets: '…', closure: '…' } },
];
```

| field | rule |
|---|---|
| `id` | `a-z`, `0-9` and `-`, 1 to 60 characters, unique. It is also the photo prefix: `assets/images/<id>-1.jpg`, `<id>-2.jpg`, … |
| `name` | required, up to 80 characters |
| `kind` | `umar`, `rucsac`, `borseta` or `tote` |
| `photos` | 1 to 12. Photo 1 is the one shown on the card |
| `sold` | `true` or `false`. A sold bag stays on the site, without the order button |
| `dims` | `h`, `w`, `d` in cm, each above 0 and at most 500 |
| `madeFrom` | `null`, or a whole number from 1 to 100 (pairs of jeans). `null` hides the line |
| `tint` | `denim`, `dark`, `grey`, `pink` or `patchwork`: the placeholder colour while a photo is missing |
| `badge` | `null`, or up to 30 characters (a small label on the card) |
| `ro`, `en` | `tagline` (up to 120), `description` (up to 1500), `pockets` (up to 200), `closure` (up to 100). `ro.tagline` and `ro.description` are required. The `en` block is optional on the server, but the product page does not fall back to Romanian for English, so an empty English field shows empty |

Array order is site order. At most 200 bags.

### `assets/js/content.js`: the texts

```js
const CONTENT = { ro: { 'nav.collection': '…', … }, en: { 'nav.collection': '…', … } };
```

Keys are flat and dotted (`hero.title1`, `story.p1`). Both languages must have the same keys.
The key `x.y` is linked to the element with `data-i18n="x.y"` in `index.html`.

- The panel can change the text of existing keys. It cannot add keys. A new key needs a hand
  edit in both `content.js` and `index.html`.
- Values are up to 2000 characters. An empty English value shows the Romanian text, because
  `t()` in `app.js` falls back to Romanian. The panel requires every Romanian value.
- The only HTML allowed in a value is an anchor, `<a href="#…">text</a>`, where the target is
  a section of the site. The panel's help lists `#contact`, `#collection`, `#story` and
  `#process`. Any other `<` or `>` is refused by the panel.
- `seo.title` and `seo.description` feed `document.title` and the meta description. See §9
  for the title limitation.

### `data/posts.json`: the blog

```json
{ "posts": [
  { "id": "articol-1", "date": "2026-10-03",
    "photos": [ { "w": 1000, "h": 1250 } ],
    "ro": { "title": "…", "body": "…" },
    "en": { "title": "", "body": "" } }
] }
```

- `id`: same rule as bag ids. It is also the folder: photos are at `assets/blog/<id>/<n>.jpg`.
  While an article is unpublished, its id follows its title. After the first publish it stays.
- `date`: `YYYY-MM-DD`, between 2000 and 2100.
- `photos`: 1 to 30 entries. Photo 1 is the cover.
- `ro.title` is required (up to 160 characters). `body` is up to 20000 characters. English is optional.
- At most 300 posts.

**Current status:** the panel saves posts, but nothing renders them yet. There are no article
pages and no list on the home page. `buildEntries` says article pages come in a later stage,
and no code reads `body`.

### Photos

- `/api/blob` accepts JPEG only (it checks the file signature), up to 900 KB after decoding.
- The panel accepts JPEG, PNG and WebP. Anything that is not already a small JPEG is redrawn as
  a JPEG with a maximum side of 2000 px, and compressed until it is under about 860 KB. Nothing is
  cropped.
- Each new photo is uploaded on its own, so no single request gets large.
- The server keeps a `.webp` file next to each bag `.jpg` in step with it (moves, deletes). The
  panel never creates `.webp` files, and no page references them yet: `index.html` has no
  `<picture>` element, although a comment in `server/api.js` says pages request one.

## 4. Secrets and configuration

| name | where it lives | purpose |
|---|---|---|
| `ADMIN_PASSWORD` | Worker secret in Cloudflare; `.dev.vars` locally | the panel password, compared in constant time |
| `GITHUB_TOKEN` | Worker secret in Cloudflare; `.dev.vars` locally | token for the GitHub API. Only the server sees it; the browser never does |
| `GITHUB_REPO` | optional override | default `gabimaftei/nomisannele` |
| `GITHUB_API_URL` | optional override | default `https://api.github.com`. Used by the tests and the dev server |
| `GITHUB_BRANCH` | optional override | default `main` |
| `PASSWORD_LIMIT` | binding in `wrangler.jsonc`, not a secret | counts wrong passwords: 10 per 60 seconds, per IP |

If `ADMIN_PASSWORD` or `GITHUB_TOKEN` is missing, every `/api` call answers with a message that the
panel is not fully configured.

`.dev.vars` holds local test values. It is git-ignored and must never be committed. Do not copy
its values into docs, issues or chat.

## 5. Cloudflare state

- Worker name `nomis-annele`, compatibility date `2026-09-01`, static files from the repo root
  (binding `ASSETS`), unknown addresses answered with `404.html`.
- `run_worker_first` is `["/api/*"]`: only the API goes through the Worker. This needs
  `wrangler` 4.36 or newer, for the rate limit binding.
- **Missing:** `account_id` in `wrangler.jsonc` (`wrangler` asks for it at deploy time), and a
  custom domain. There are no routes yet.
- `workers_dev` is `true`, so the `workers.dev` address stays on until the domain is connected
  (planned for stage 4).
- `CANONICAL` in `worker.js` is `null`, so there are no redirects (no `www`, no `http`).
- The panel and `/api/*` only work where the Worker runs. GitHub Pages serves static files only.

**When the domain is bought and connected:**

1. Set `CANONICAL` in `worker.js` to the bare domain, for example `nomisannele.ro`.
2. In `wrangler.jsonc`, add `routes` with `custom_domain: true`, set `workers_dev` to `false`, and
   change `run_worker_first` to `["/*", "!/assets/*"]` (see the comment there).
3. Change the canonical link and `og:url` in `index.html`. The sitemap and the 404 page are
   generated from that address.

A domain suggestion: `nomisannele.ro` (about €10–15 a year, from RoTLD, Namecheap or Cloudflare).

The absolute addresses in `index.html` (`<link rel="canonical">`, `og:url`, `og:image`) and the
links to the repo still say `gabimaftei.github.io/nomisannele` on purpose. They change only when
the domain is live.

## 6. Publishing

**From the panel:** "Publică" builds one commit with the generated files, the new or moved photos,
and the removed ones, then moves `main` to it. The commit message is the "Ce ai schimbat" text, followed by
"Salvat din panoul de la /admin.". The site updates after the hosting picks up the commit,
which the panel describes as a few minutes.

**By hand:**

```bash
git add -A && git commit -m "Add new bag" && git push
```

Hand edits to the generated files (`products.js`, `content.js`, `index.html` parts) are
overwritten by the next panel save. Make content changes in the panel. Use git for code and
for files the panel does not own.

**Conflicts (HTTP 409):** the panel sends the commit it started from. If `main` has moved since
then, because of another tab or a commit made by hand, the server refuses the publish and writes
nothing. The panel then says that something else was published and asks the user to copy the text,
reload and publish again. This is GitHub's fast-forward check: the branch update is not forced.

## 7. How it is built, and why it is safe

- **No database.** The data is the files in this repo. Every publish is a commit, so history
  shows every version.
- **Visitors are not tracked.** The site's own code sets no cookies and includes no analytics or forms. The
  only saved setting is the language choice, in the browser's `localStorage` (key `na-lang`).
  The password limiter counts wrong passwords per IP address, and only for the panel.
- **No third-party requests.** The fonts are served from `assets/fonts/`, not from Google, so
  no visitor data goes to Google. Licences are in `assets/fonts/OFL.txt`.
- **Strict CSP.** Both `index.html` and `admin/index.html` have a Content-Security-Policy meta
  tag with `default-src 'self'`, `style-src 'self'`, `script-src 'self'` and `connect-src 'self'`.
  `_headers` adds `frame-ancestors 'none'`, HSTS, `nosniff` and a strict referrer policy.
- **No inline styles.** No `style` attributes, no inline scripts, no `element.style`. State is kept
  in CSS classes. The one exception: `app.js` builds the scroll-lock stylesheet with
  `adoptedStyleSheets`, which the policy does not treat as inline. The tests check that the
  generated HTML has no `style=`.
- **Escaping.** All text from the panel goes through `esc()` in `server/render.js` before it goes
  into HTML. The panel never uses `innerHTML` with its own text.
- **Passwords.** The comparison is constant-time. Each wrong password waits 700 ms. After ten
  wrong passwords within 60 seconds from one IP address, the next wrong attempt locks that address
  out for 15 minutes. A correct password is never counted. The limit is approximate: each Cloudflare data centre counts on its own.
- **Accessibility:** text passes WCAG AA contrast (the weakest pairing is 4.78:1 against a 4.5
  requirement), tap targets are at least 44px, the bag window traps keyboard focus and closes on
  Escape, and the background is made inert while it is open.

### Cache and version markers

- `_headers`: fonts for a year (immutable); photos and blog files for one day; CSS and JS for one
  hour; HTML with the default rule, so a publish shows at once.
- **When you change `styles.css` or `app.js`,** raise the `?v=` number in `index.html` (now `28`).
  **When you change anything in `admin/`,** raise the `?v=` number in `admin/index.html` (now `1`).
  Without this, people may keep an old copy from their browser cache for up to an hour.
- `products.js` and `content.js` are loaded with `?h=<hash>`. The hash is set automatically when the
  panel publishes or `build-site` runs, so there is nothing to bump by hand.

  posts. The tone and the story are a guess; whoever lived it should read it and correct it.
- **A real photo for that section.** `assets/images/story.jpg` takes over automatically. Until it
  exists, the section shows `patchwork-1.jpg`.

  "Titlu" field in the panel changes `document.title` only after JavaScript runs, so crawlers that
